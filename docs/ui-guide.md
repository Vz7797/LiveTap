# 管理后台界面规范

本文落实 `docs/design.md` 第 11 节的界面规则，具体颜色值见其 11.2 节，对应实现集中在 `web/src/index.css`。页面复用现有共享组件，不另建同用途的样式或动效体系。

## 1. 基本原则

- 清透底色、按用途点缀、全宽左对齐、静态常驻内容；所有页面共用令牌、共享组件、动效设置与页面懒加载。
- 历史曲线不推算、缺失指标不填假值、操作反馈以服务端返回为准。
- 登录与首次改密在进入后台前完成。凭据输入为空表示未修改，界面只显示“已配置”状态，不回显秘密。实时连接中断时保留最近数据并明确提示。

## 2. 颜色与材质

| 元素 | 使用规则 |
|---|---|
| 页面与卡片 | `background`、`card`、`popover` 分层，正文使用对应 `foreground`；深色为蓝墨与稍亮蓝色卡片，浅色为云白和浅蓝 |
| 次级文字 | `muted-foreground`；坐标、辅助说明可用 `faint`，不靠过低透明度隐藏必要信息 |
| 品牌黄 | `primary`，用于主按钮、选中态和少数关键数据（当前时段、第一名、弹幕）；主卡片中性底 |
| 消息类型与状态 | 图形用 `--c-*`，文字用 `--ink-*`；按 `TYPE_META` / `STATUS_META` 统一含义 |
| 图标底块与头像 | 图标默认按用途使用同色浅底；头像默认浅蓝、在线浅绿，停用时弱化；显示名字首字，不加彩圈与旋转 |
| 语义标签 | 浅色主题同色底 10%、深色 14%；状态同时带短文字，不能只靠颜色识别 |
| 图表 | 堆叠图用色带：每层实色填充（透明度由 `--band-main` / `--band` 控制，深色主题更高），层间用卡片底色细线分隔，不画彩色描边；图例悬停可高亮单层；文字使用文字色 |
| 直播间迷你曲线 | 按状态着色：采集中绿色，等待蓝色，异常沿用状态色，停用灰色；不按房间随机分配颜色 |
| 消息与接入方统计 | 消息排行、连接、推送曲线与正常额度用蓝色；推送量用浅绿；丢弃与接近额度上限用警告色；热词统一浅黄标签 |
| 实验室结论 | 纯色卡片、蓝色细边与关键数字，说明文字沿用正文色，不使用整块渐变 |
| 边框与阴影 | 使用 `border`、`border-strong` 和中性卡片阴影；不加彩色阴影、光晕或外发光 |
| 浮层与背景 | 纯色或半透明纯色；无毛玻璃、彩虹圈、大面积渐变或动态背景 |

**克制靠“彩色用得少”，不靠把颜色调灰调脏。** 用到的颜色保持干净、中等饱和；颜色跟着重要性走：弹幕用品牌黄，点赞用柔和玫瑰色，资源与请求图表按用途着色。图表保留图例、标签和层间分隔，彩色集中在图标和数据区域。浅色主题的小字使用加深的 `--ink-*`，新增页面不硬编码另一套颜色。普通文字对比度以至少 4.5:1 为目标，颜色调整后同时检查深浅主题。

## 3. 字号与信息层级

| 用途 | 常用字号 | 规则 |
|---|---|---|
| 页面标题 | 手机 20 px、桌面 24 px | 约 600 字重，左对齐 |
| 卡片标题 | 15 px | 约 600 字重，约 20 px 行高，手机允许换行 |
| 正文与主要操作 | 14 px | 优先保证可读性，避免整屏全部使用小字 |
| 辅助说明 | 12 px | 行高约 20 px，使用次级文字色 |
| 时间、标签、坐标 | 10～11 px | 只用于辅助信息，不能承载主要说明 |
| 常规统计数字 | 26～32 px | `Geist Mono`、等宽数字，保持位数变化时的稳定性 |
| 总览主数字 | 手机约 30 px、桌面约 38 px | 仅少量关键数据使用较大字号 |

中文使用系统字体，数字使用共享 `num` 类。标题不为挤出按钮而省略；手机端优先让操作区换行。固定长度的房间名称、编号或非关键说明确需省略时，仍应保留可查看完整内容的途径。

## 4. 间距、圆角与布局

- 按 4 px 基础步长组织间距：4 / 8 / 12 / 16 / 20 / 24 px。卡片间距一般为 12～16 px，卡片内边距一般为手机 16 px、桌面 20～24 px。
- 页面与顶栏铺满侧边栏右侧全部可用宽度，手机左右约 16 px、桌面约 24 px，不使用整页居中的 `mx-auto` 最大宽度容器。
- 页面标题、说明、筛选与操作按阅读顺序左对齐；局部图表的中心数字与图例可按其信息结构排布。
- 页面级卡片常用 24 px 圆角，内部区域常用 12～16 px，标签约 6 px，按钮和状态胶囊可用全圆角。复用 `Card`、`CardHeader`、`PillButton` 等组件。
- 总览用命名区域（`grid-template-areas`）排版：手机、768 px、1280 px（12 列）、1920 px（24 列）各一套，保证每行铺满、不留空洞；会被拉高的卡片要有能伸缩的内容（如主卡片的“今日节奏”），不能出现大块空白；直播间卡片按可用宽度增加列数，当前在 1920 px、2240 px 视口继续增加列数。
- 宽屏不把每张卡片无限拉长；手机允许工具栏、图例与卡片操作换行，图表根据自身宽度抽取坐标标签。
- 打开直播间详情时保留淡化占位卡片，不留下纯黑空块；顶部统计的标签、单位与数字含义一致。
- 接入方、代理导入和设置弹窗限制在视口高度内，内容超出时内部滚动，手机端仍能访问底部操作。

## 5. 响应式与可用性

| 场景 | 检查内容 |
|---|---|
| 桌面，至少 1280 px | 内容全宽左对齐，侧栏与顶栏一致，网格充分利用可用空间 |
| 手机，375～390 px | 主标题和图表卡片标题完整，操作区可换行，无页面横向滚动 |
| 深浅主题 | 中性层级清楚，标签与图例可读，主按钮文字和焦点可识别 |
| 键盘与触控 | 可点击卡片支持键盘打开；按钮有可见焦点；操作不依赖悬停才能完成 |
| 消息查看 | 保留关键字与类型过滤、手动暂停、鼠标悬停暂停；手机可使用显式暂停 |

## 6. 动效规则

默认使用“精简”，系统设置可选择“标准”。操作系统启用“减少动态效果”时始终按精简处理，覆盖标准设置。两种模式都不启用常驻装饰循环。

| 场景 | 精简 | 标准 |
|---|---|---|
| 状态圆点、头像、背景、雷达 | 静态 | 静态 |
| 数据、图表、进度条刷新 | 直接更新 | 直接更新，不做图表补间 |
| 普通数字 | 直接显示 | 直接显示 |
| 显式标记的少数关键数字 | 直接显示 | 数值变化时执行一次约 180 ms 过渡 |
| 点击、悬停、切换标签 | 必要的短反馈 | 150～250 ms 简单缓动 |
| 打开与关闭面板 | 简单淡入与小幅位移 | 简单淡入与小幅位移，约 180 ms |
| 主题切换 | 直接切换 | 可使用 220 ms 圆形扩散 |
| 新消息插入 | 直接更新，不做布局动画 | 直接更新，不做布局动画 |

不使用弹簧回弹、逐条列表模糊进场、每次 tick 的布局测量动画。进行中的用户操作可以有加载指示，操作结束后必须停止或卸载。保留 beUI 组件文件头的来源注释。

消息统计条、热词、排行、账号卡片、告警与日志直接显示或更新。代理检测中显示“检测中”，结果出来后再显示延迟值，不用随机跳动数字表现进度。实验室进度条直接更新宽度，结果表格不逐行进场。

## 7. 数据刷新与性能预算

| 项目 | 约束 |
|---|---|
| 真实数据刷新 | WebSocket 每 2.5 秒快照；连接失败回退 15 秒轮询；页面隐藏时关闭实时连接，回到前台刷新并恢复 |
| 总览订阅 | 各卡片按需选择数据，保持不相关组件的引用稳定 |
| 直播间订阅 | 目录只关注名称、状态、来源、标签等筛选摘要；卡片与打开的详情独立订阅各自房间 |
| 列表重渲染 | 使用 selector、相等判断与必要的 `memo`，避免整个页面随每次 tick 更新 |
| 实时消息 | 每房间内存缓存最多 200 条，全局 Feed 与共享列表最多 100 条，行无布局动画；详情读取该房间缓存 |
| 实时日志 | 内存缓冲与显示上限分开说明，列表最多显示 100 条，行无进场与布局动画 |
| 图表 | 更新直接设置 SVG 路径或属性；实时窗口保留 72 点，历史按时间区间聚合到最多 120 个点 |
| 页面加载 | `React.lazy` 按页面加载，主入口不静态导入全部页面 |
| 静置 CPU 目标 | 总览单个渲染线程的平均忙碌占比尽量低于 1% |
| 长任务目标 | 静置 10 秒、滚动 5 秒的录制中，超过 50 ms 的长任务为 0 |

CPU 与长任务行是**性能目标，尚不能据此宣称已实测通过**。CPU 口径需说明是单渲染线程占比还是整机 / 进程占用，比较前后必须使用相同口径、视口、主题和动效模式。包体积记录实际构建产物，不把懒加载后的主入口大小当成所有分包的总大小。

## 8. 验证与产物

- 代码检查使用 `cd web && pnpm build`；开发端口固定为 5310。
- 界面修改按桌面、手机与深浅主题自测并截图，检查横向滚动、控制台错误、标题与坐标重叠。
- 使用 Chrome DevTools Performance 记录总览静置 10 秒和滚动 5 秒，报告相同口径下的 CPU、长任务和构建包体积，并保存截图。
- 自测截图和实测结果不提交到仓库；正式说明维护在 `docs/`。
